## Số đo

- **Bộ nhớ Working Set / RSS của cây tiến trình Chromium**:
  - **1 Tab đang mở trang thật** (`12` tiến trình browser + network + storage + renderer): **`627.9 – 638.1 MB`**.
  - **2 Tabs đang mở song song**: **`802.5 – 865.7 MB`** (chênh lệch thêm ~`175 – 235 MB`/tab).
  - Tiến trình bridge `@playwright/mcp@0.0.85` (Node/Bun): ~`55 – 70 MB` mỗi phiên.
- **Bảng phân loại đầy đủ 25 tool của `@playwright/mcp@0.0.85` (dùng cho `ClassifyBrowserTool` ở `P3.05`)**:

| Tên tool (`@playwright/mcp@0.0.85`) | Lớp (`ToolClass`) | Ghi chú điều kiện bảo vệ ở `P3.05` |
|---|---|---|
| `browser_navigate` | **`R`** *(Allowlist)* | **Bắt buộc** kiểm `AllowedURL(args.url)` (chỉ `http`/`https`, chặn loopback/private IP/link-local/metadata + kiểm lại IP sau phân giải DNS) trước khi chuyển tiếp. |
| `browser_navigate_back` | **`R`** *(Allowlist)* | Quay lại trang trước trong lịch sử tab. |
| `browser_snapshot` | **`R`** *(Allowlist)* | Đọc cây accessibility YAML kèm mã `[ref=...]`. |
| `browser_find` | **`R`** *(Allowlist)* | Tìm văn bản trong trang hiện hành. |
| `browser_wait_for` | **`R`** *(Allowlist)* | Chờ văn bản/thời gian xuất hiện, không tác động ngoại cảnh. |
| `browser_console_messages` | **`R`** *(Allowlist)* | Đọc log console của trang. |
| `browser_network_requests` | **`R`** *(Allowlist)* | Liệt kê lịch sử request mạng đã diễn ra của trang (chỉ đọc). |
| `browser_take_screenshot` | **`R`** *(Có điều kiện)* | Chỉ xếp `R` khi **không truyền `filename`** (trả ảnh base64 về bộ nhớ); nếu có `filename` phải kiểm phạm vi đường dẫn hoặc ép rỗng để tránh ghi file tùy ý. |

Đề xuất **chặn cứng ở proxy `max mcp`** đối với mọi vai trò trước Phase 4. |

## Quyết định

- **Cách triển khai chọn cho Production (`Spec 8.10` / `P3.05`)**:
  - **Mô hình 2 container trên Docker Compose** (`max` + `cloakbrowser` chạy `cloakhq/cloakbrowser` với lệnh `cloakserve --data-dir=/data --keep-profiles` và `CLOAKBROWSER_LICENSE_KEY`). Khi dev cục bộ chưa cấu hình key, `adapter/browser` cho phép fallback sang Chromium headless cục bộ qua cùng giao diện CDP `/json/version?fingerprint=<seed>` để chạy test tích hợp không phụ thuộc license.
  - Mỗi chỗ trình duyệt (`MAX_BROWSER_SEATS`) dự phòng tối thiểu **`~700 MB` RAM** (1 tab Chromium + Playwright MCP shim); luôn kiểm ngưỡng RAM trống `>= 1 GB` trước khi cấp chỗ mới.

## Việc phải sửa trong spec/kế hoạch

1. **Bắt buộc bọc `@playwright/mcp` sau cổng proxy của `max mcp` thay vì gắn trực tiếp vào `session/new` của `agy acp` (`P3.05` dòng 339 — kết hợp phát hiện từ `S0c` Mục 3c)**:
   - Ở `S0c`, thực nghiệm chứng minh `agy acp` **không gửi `session/request_permission`** cho các tool thuộc MCP server khai trong `session/new`. Nếu `driver/agy` gắn trực tiếp `@playwright/mcp` vào phiên của `agy`, agent sẽ gọi thẳng `browser_navigate("http://169.254.169.254/...")` hoặc `browser_click` mà **đi vòng qua cả `Acquire` (giới hạn chỗ), `AllowedURL` (chống SSRF) lẫn `ClassifyBrowserTool` (`suggest` -> `Deny`)**!
   - Vì vậy ở `P3.05`, `max` phải nối nội bộ tới `@playwright/mcp` bằng `mcpclient` (giống kiến trúc Gateway ở `P3.06`) và tái xuất các tool `browser_*` qua chính `max mcp` server — đảm bảo 100% lời gọi trình duyệt trên cả 3 CLI (`agy`, `claude`, `codex`) đều bị kiểm soát tập trung bởi `AllowedURL` + `ClassifyBrowserTool` + `Acquire`!
2. **Chặn cứng 3 tool lách SSRF (`browser_evaluate`, `browser_run_code_unsafe`, `browser_network_request`) trong `P3.05`**: `@playwright/mcp@0.0.85` có sẵn `browser_network_request` và `browser_run_code_unsafe` cho phép gọi thẳng mạng nội bộ mà không đi qua `browser_navigate`; bộ lọc ở `P3.05` không mở 3 tool này cho agent.
3. **Đóng phiên trình duyệt bằng CDP `Browser.close` trước khi thu hồi tiến trình (`P3.05`)**: Khi hết hạn giữ chỗ hoặc tắt dịch vụ, gửi lệnh CDP `Browser.close` (thay vì `SIGKILL` ngay) để Chromium kịp ghi bảng SQLite `Cookies` và `Local Storage` xuống thư mục profile bền.
