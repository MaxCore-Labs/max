# S2: `agentmemory` với nhiều agent

Ngày: 2026-11-19   Phiên bản công cụ & phần cứng: `@agentmemory/agentmemory` 0.9.33 (`iii-engine` 0.25.1, Bun 1.4.5), đối chứng với `modernc.org/sqlite` v1.62.0 FTS5 trên Go 1.27.4 (`linux/amd64`, `CGO_ENABLED=0`, container Debian 12 có `--init`, CPU 12 luồng Intel i5-11400 @ 2.60 GHz, ổ NVMe SSD / overlayfs trên `ext4`)

Lệnh chạy tái lập trên Linux:
```bash
CGO_ENABLED=0 GOOS=linux GOARCH=amd64 go build -o s2 ./spikes/s2
./s2 -target 200000 -agents 10000 -workers 32 -max-write-sec 45
```

## Số đo đối chứng trên Linux

| Chỉ số đo thực nghiệm (Linux `x86_64`) | `@agentmemory/agentmemory@0.9.33` *(ở `N = 3.942`)* | Phương án dự phòng **SQLite FTS5** *(ở `N = 200.000`)* | Nhận xét đối chiếu công bằng |
|---|---|---|---|
| Tiến trình hệ điều hành phụ | `7 – 9` tiến trình (`iii` + compose workers) | **`0` tiến trình** (nhúng trong binary `max`) | Loại bỏ hoàn toàn cụm daemon ngoài |
| Tốc độ ghi `1 dòng/giao dịch` *(chuẩn production)* | `87,6 writes/s` (qua HTTP + khóa toàn cục; giảm dần theo `N`) | **`1.952 tx/s`** *(trên DB đã có `200.000` dòng; nạp lô `500/tx` đạt `24.581 dòng/s`)* | **Nhanh hơn ~`22x`** ở cùng chế độ 1 bản ghi/lần |
| Độ trễ tìm kiếm `p50` / `p95` (`limit = 5`) | `127,19 ms` / `186,49 ms` *(qua HTTP, ở `N = 3.942`)* | **`5,26 ms` / `9,34 ms`** *(trong tiến trình, ở `N = 201.000`)* | Nhanh hơn ~`20x` dù tập dữ liệu lớn gấp `50x` |
| Độ phủ theo `agentId` (`TopicHalf` / `UniqueRecall@5`) | `500/500` / `500/500` ở `N = 3.942` *(chưa đo ở `200k`; lọc hậu kỳ trên top `1.000` toàn cục)* | **`500/500` / `500/500` ở `N = 201.000`** *(giao danh sách đảo `scope_tok` trực tiếp trong FTS5)* | Đảm bảo phân vùng cứng theo agent/team ở quy mô lớn |
| Bộ nhớ thực tế (`PSS` / `VmHWM`) | Rỗi `222,9 MiB` -> sau `3,9k` dòng **`396,6 MiB` PSS** (`418,1 MiB` RSS) | Trước `14,6 MiB` -> sau `201k` dòng **`115,4 MiB` PSS** (**`115,0 MiB` `VmHWM`**, trần cache `<= 96 MiB`) | **Nhẹ hơn ~`3,4x` PSS** (so ở `2%` tải của `agentmemory` vs `100%` tải của FTS5) |

## Quyết định

1. **Chọn phương án dự phòng `SQLite FTS5` sau port `EpisodicMemory`** (theo nhánh dự phòng có sẵn tại cổng Phase 0 plan A dòng 212 và plan B `P3.02` dòng 305: `internal/adapter/sqlite/memory.go`). Lý do chính đã xác minh: loại bỏ `7–9` tiến trình phụ và `~223–397 MiB` PSS nền của `agentmemory`, loại bỏ khoảng trễ dựng lại BM25 sau khởi động lại, và tránh cơ chế lấy ứng viên toàn cục rồi mới lọc theo `agentId`.
2. **Đặt chung trong file SQLite chính `max.sqlite3` (không tách file DB riêng)**:
   - Khi bảng `episodic_memories` và `episodic_fts` nằm chung trong `max.sqlite3`, thao tác `Remember` cuối mỗi run ghi nguyên tử ngay trong cùng giao dịch kết thúc run (`Finalize`), **không cần qua bảng `outbox` `memory.remember`** (nếu tách file qua `ATTACH` ở chế độ WAL thì giao dịch không nguyên tử giữa hai file).
   - Giới hạn tổng page cache của SQLite bằng cấu hình bất đối xứng: `1` kết nối ghi `cache_size(-32768)` (`32 MiB`) + tối đa `4` kết nối đọc `cache_size(-16384)` (`16 MiB` × 4 = `64 MiB`) -> **trần bộ nhớ đệm trang `<= 96 MiB`**.
3. **Thiết kế đầy đủ cho `P3.02` (đã kiểm chứng bằng unit test tại `spikes/s2/s2_test.go`)**:
   - **Lược đồ hỗ trợ cả phạm vi riêng (`private`) và phạm vi nhóm (`team` / `shared` có ghi tác giả theo Spec `8.9.4`)**:
     - `episodic_memories(id PRIMARY KEY, author_agent_id, team_id, scope CHECK(scope IN ('private','team')), conversation_id, kind, content, created_at) WITHOUT ROWID` giữ nguyên văn tiếng Việt gốc.
     - `episodic_fts USING fts5(scope_tok, content_norm, memory_id UNINDEXED, tokenize = 'unicode61 remove_diacritics 2')` lưu chỉ mục b-tree phân đoạn của FTS5.
   - **Mã hóa token phân vùng đơn ánh (1 token chữ-số duy nhất, không bị `unicode61` cắt theo dấu câu)**:
     - `agentToken(id) = "ag" + hex.EncodeToString([]byte(id))` và `teamToken(id) = "tm" + hex.EncodeToString([]byte(id))`.
     - Ký ức `private` ghi `scope_tok = agentToken(author)`; ký ức `team` (khi cấu hình team bật chế độ `shared`) ghi `scope_tok = agentToken(author) + " " + teamToken(team)`. Khi truy vấn luôn giữ kèm điều kiện chặn ở `JOIN` (`m.author_agent_id = ? OR (m.scope = 'team' AND m.team_id = ?)`) và trả kèm `author_agent_id` để khối `<recall>` ghi rõ tác giả.
   - **Chính sách tiếng Việt nhất quán**: dùng `tokenize = 'unicode61 remove_diacritics 2'` kết hợp hàm chuẩn hóa `đ/Đ -> d/D` phía Go (`foldVNForFTS`) cho cả cột chỉ mục `content_norm` lúc ghi lẫn chuỗi truy vấn lúc tìm, giúp cả truy vấn có dấu lẫn không dấu (kể cả nguyên âm hai dấu như `cổng`, `khắc`, `lỗi` và chữ `đối`/`doi`) đều khớp nhất quán trong khi vẫn trả về văn bản gốc có dấu từ `episodic_memories.content`.
   - **Chính sách tự quên / giới hạn lưu giữ (retention)**: định kỳ (trong lượt bảo trì/scheduler) chạy `pruneEpisodicMemories` xóa các bản ghi quá hạn tuổi (ví dụ `> 90` ngày) hoặc vượt trần số lượng mỗi agent (ví dụ `> 2.000` mục/agent) ở **cả `episodic_fts` lẫn `episodic_memories` trong cùng một giao dịch**.
   - **Chuẩn hóa truy vấn an toàn**: tách từ chữ-số Unicode và bọc ngoặc kép từng token trước khi đưa vào `MATCH` để ký tự đặc biệt (`:`, `*`, `"`, `-`, `NEAR`) không thể gây lỗi cú pháp hoặc thoát khỏi điều kiện `scope_tok`.
