## Quy trình build tái lập (bắt buộc theo thứ tự)

Vì `spikes/s3/main.go` dùng `//go:embed all:web/build` còn `web/build/` nằm trong `.gitignore`, luôn phải biên dịch gói tĩnh của `web/` trước khi biên dịch hoặc chạy `go test` phía Go:

```bash
cd spikes/s3/web && bun install --frozen-lockfile && bun run check && bun run build
cd .. && CGO_ENABLED=0 go test ./... && CGO_ENABLED=0 go build -o s3 .
./s3 -self-test
bun run browser-check.mjs
```

Ở Phase 1 (`P1.01` / `P1.25`), `Makefile` và workflow CI bắt buộc chạy bước `bun install --frozen-lockfile && bun run build` trong `web/` (hoặc tạo thư mục giữ chỗ khi chạy unit test các gói không chạm `httpapi`) trước khi gọi `go test ./...` và `go build ./cmd/max`.

## Quyết định

- **Cấu hình chuẩn chốt cho `web/` và `internal/adapter/httpapi` ở Phase 1 (`P1.25`, `P1.31`)**:
  - Cấu hình `adapter-static` trực tiếp trong `vite.config.ts` với **`fallback: '200.html'`** và **`precompress: true`**:
    ```ts
    sveltekit({
      adapter: adapter({ pages: 'build', assets: 'build', fallback: '200.html', precompress: true, strict: true })
    })
    ```
    *(Dùng `200.html` thay vì `index.html` để tránh xung đột nếu về sau có trang tĩnh cần prerender; đồng thời giữ `export const ssr = false; export const prerender = false;` ở `src/routes/+layout.ts`).*
  - Quy tắc phân luồng bắt buộc của HTTP handler phía Go:
    1. `/api` hoặc `/api/*` không khớp route -> trả **`404` JSON**.
    2. Khớp file thật trong `web/build` -> phục vụ bản nén sẵn `.br` hoặc `.gz` theo `Accept-Encoding` (`Vary: Accept-Encoding`); gắn `Cache-Control: public, max-age=31536000, immutable` cho `/_app/immutable/*` và `public, max-age=3600` cho tài sản tĩnh khác.
    3. Không tìm thấy file nhưng đường dẫn nằm dưới `/_app/` hoặc có phần mở rộng file (`path.Ext(clean) != ""`) -> trả **`404`**, tuyệt đối **không** trả HTML SPA (tránh lỗi trình duyệt nhận HTML cho chunk `.js` cũ sau khi nâng cấp bản mới).
    4. Các đường dẫn điều hướng SPA còn lại (`/`, `/activity`, ...) -> trả `200.html` với `Cache-Control: no-cache`.
  - Quy tắc kết nối SSE bền vững (`Spec 8.12` / `P1.24` / `P1.25`):
    - Phía Go gửi bình luận `: ping\n\n` mỗi `15s` để giữ kết nối qua Tailscale Serve / Caddy / nginx và phát hiện sớm peer chết; kèm mã `bootId` của tiến trình máy chủ.
    - Phía Svelte (`events.svelte.ts`): dùng khóa tăng đơn điệu phía client cho `{#each}` (tránh lỗi trùng khóa khi server khởi động lại về `seq = 1`), xóa trạng thái luồng cũ / tải lại snapshot trong `onopen` sau khi đứt kết nối (`hadError`) hoặc đổi `bootId`, và chủ động khởi tạo lại `EventSource` theo backoff (`0.5s -> 5s`) nếu `readyState === EventSource.CLOSED`.

## Việc phải sửa trong spec/kế hoạch

1. **Cập nhật 4 thay đổi bắt buộc của SvelteKit 3 cho task `P1.25` (Khung UI)**:
   - Không tạo `svelte.config.js` (`config_file_unsupported`); cấu hình `adapter-static` (`fallback: '200.html'`, `precompress: true`) đặt trong `vite.config.ts`.
   - Ghim peer dependencies `@sveltejs/kit` 3.x đi cùng `vite@^8.0.12` và `typescript@^6.0.0`.
   - `tsconfig.json` kế thừa `"extends": "$app/tsconfig"`.
   - Dùng Node subpath imports `"#lib/*": "./src/lib/*"` trong `package.json` thay cho `$lib` đã gỡ ở SvelteKit 3.
2. **Quy ước bắt buộc import icon theo subpath (`Spec 8.13.1` / `P1.31`)**: Mọi nơi trong `web/` import icon theo `@lucide/svelte/icons/<ten-icon>` để giữ thời gian build Vite ở mức `~0.26s` thay vì `> 4s`.
3. **Định vị và kẹp biên phần tử `[popover]` cho component `Menu.svelte` (`Spec 8.13.1` / `P1.31`)**: Đặt `inset: auto; position: fixed; margin: 0`, tính `left`/`top` từ `triggerEl.getBoundingClientRect()` và `popoverEl.getBoundingClientRect()` với kẹp biên ngang (`innerWidth`) + tự lật lên trên / kẹp biên dọc (`innerHeight`), đồng thời gắn listener `resize` và `scroll` (capturing) khi menu đang mở để cập nhật vị trí hoặc đóng menu khi nút neo cuộn khuất khỏi khung nhìn.
